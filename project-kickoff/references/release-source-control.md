# 来源与Git交付

用于正式版本来源核定、旧工程接手和长期未提交成果整理；普通小改只检查受影响范围，不机械建立新台账。

## 核定可复建基线

- 将功能范围、完整来源索引、后继补丁及应用顺序、构建脚本/锁文件/工具链、网页/安装包、签名身份、正式部署和回退对象关联起来。入口尽量复用现有材料。
- 索引的角色标签不是提交许可。逐项区分自有源码、测试/文档、可重新取得的依赖、模型、构建产物、秘密及真实用户资料；按项目规则确定哪些进入Git，其余记录合法取得方式、版本和摘要。签名身份可记录，签名秘密不写入普通清单。
- 旧索引中的“未发布”等历史状态由后继正式回执解释，不覆盖原记录；当前根目录或较旧Git提交都不能直接覆盖后继正式源码。
- 来源存在且摘要匹配，只证明材料完整。宣称“可复建完成”须有隔离环境重建和相称产物比对；这不阻塞源码整理、修复或分批Git交付，各阶段按实际状态报告。若时间戳、签名或归档顺序不确定，比较有效负载、资源、版本和签名身份，不强求无业务意义的整包逐字节一致。
- 复建缺依赖或只有原机私有路径时，记录确切缺项和恢复方式，不能将“本机能运行”称为另一台机器可恢复。未知构建/部署结果先核原操作，不重做未知发布。

## 按任务提交与推送

1. 本地修改/提交先核分支、索引及受影响差异；实际推送前再核远端地址、真实HEAD、待推送范围及部署联动。远端检查不作为本地修改的前置；Git推送不是默认产品部署授权。
2. 已有改动按本任务、其它任务和禁止提交资产分类。使用明确路径或经核对的补丁暂存，不整体加入混合工作区，不覆盖、删除或重置其它任务成果。
3. 核暂存范围，完成与变化相称的检查。推送会包含未推送祖先，推送前先以范围清单、文件类型、资产/秘密扫描和部署影响定位风险，再定向阅读必要差异；继承有效旧证据，不要求逐条重做历史业务验收。不靠另造远端提交、强推或重写历史掩盖问题。
4. 一个可验收任务及时形成清晰可回滚的提交；跨功能但不可分割的发布基线须说明依赖，不为凑小提交制造不能工作或来源不明的中间版本。不倒填旧日期。
5. 在已有对应授权内推送指定仓库/分支，核远端HEAD与本次预期提交一致。遇并发更新先读取差异，按项目合并规则处理；超时或结果未知先只读查询，不盲目再次修改远端。
6. 报告本地提交、远端推送、产品部署及用户验收的各自结果。仅整理Git时不顺带修改运行环境；不跳钩子、不放宽保护来制造“已上线”。

没有本地Git写权限时，只暂停相应Git写操作，其它获准工作继续；保留现有差异及恢复入口，必要时保存补丁。不复制仓库或更换索引绕过边界，环境能力未变不重复尝试同一拒绝。换对话不是修复权限的保证，也不是继续本地工作的必需条件；同范围授权不重复索取。

## 后续节奏

每个纵向结果按“受影响实现与验证→精确提交→获准推送→远端核对”收尾；产品部署单独按必要性与授权执行。阶段结束或换对话前，记录仍未提交/未推送的确切范围和原因，不长期只靠临时冻结目录保存正式成果。历史积压另列有界批次，不把全部历史整理设置为当前产品工作的默认前置。
