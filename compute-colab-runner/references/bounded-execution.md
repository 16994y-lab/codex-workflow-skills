# 有界运行与收束

仅用于有绝对截止、长时/后台运行或跨轮恢复的已授权计算。复用已有可靠机制；本参考不是新的运行、安装、系统唤醒或自动化授权。

## 开始前

- 固定完整截止日期、时区与绝对时刻。根据实测吞吐、保存/评测和工具延迟，确定不再启动新计算的时刻及提前收尾点；预算是上限，不要求耗满。
- 核对实际解释器、配置/代码/权重身份、已有attempt/result、进程启动时间与任务归属。已有进程活跃则续观测；PID数字、旧输出文件或外壳退出码单独都不够。
- 固定当前任务的资源门槛、检查频率和停止动作；阈值不能机械继承其他任务。分段可行时优先短段保存，不把环境预检拒绝记成模型失败。
- 采用已有、可验证的本任务进程树监督或等效边界：协作停止、限时兜底、保存策略与退出确认。只杀启动外壳可能遗留子进程；无法控制全树或验证保存时，不启动可能越过授权截止的无人值守长任务，可选择有界短任务。

## 恢复与换路

| 真实状态 | 下一动作 |
| --- | --- |
| 本任务计算仍运行 | 有界观察进度和保护状态，不重复启动 |
| 有能改变决策且仍获授权的下一步 | 按已固定合同执行，不只续写计划 |
| 单一路线受阻或固定配方失败 | 记录原因及重开条件，检查其他机制/资料路径；不自动扩围 |
| 无进展、无计算、条件未变 | 做过一次替代复核后等待明确变化，不按唤醒次数重复实验、全查或报告 |
| 截止已到或已满足提前结束条件 | 只保存、停止、核验和收束，不补跑实验 |

失败配方在有新证据或明确重试目的前保持关闭；需要估计随机波动的重复实验应事前纳入预算，而不是失败后的无边界重试。正式验收不明确时，可用标明临时的研究标准判断路线，但不能据此声称产品通过。

## 停止与证据

分别记录：计算/服务停止状态、结果保存及可恢复性、自动续跑状态。自动化需通过现有管理机制在授权范围内暂停并回读；不要等待截止最后一跳。记录根进程与所属子进程均退出的证据、停止原因、退出码和监督异常；强停、未知或异常不得仅凭外壳返回0写成自然成功。

保存记录实际结束与核验时间。迟到就报告迟到，不修改历史时刻；只处理本任务拥有的进程和资源，不结束其他任务。监督日志缺失可补做当前只读检查，但不能伪造过去回执。

实际模型时间、等待时间、准备排错、训练前向/更新、推理次数分别按可得记录报告。没有运行不写持续计算；没有充分统计不推算完成百分比或确定交期。

## 调度与唤醒边界

定时唤醒对话、启动计算与操作系统唤醒是不同能力。注册计划、手动触发成功或日志存在不证明睡眠后实际唤醒成功。若用户需要无人值守，先核当前环境支持并在已授权条件下验证真实睡眠/唤醒/工作链路；做不到就明确依赖人工开机。不得为了兑现期限擅自修改电源保护、启用系统任务或增加新权限。
